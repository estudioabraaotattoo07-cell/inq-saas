# CONSTITUIÇÃO DO INK SYSTEM

## Documento 01 — Constituição Oficial do Projeto

**Versão 1.0** (com emenda ao Artigo 3, registrada em 2026-08-06 no mesmo dia da promulgação)

---

## PREÂMBULO

O Ink System nasceu para resolver um problema real.

Não nasceu para ser um software genérico.

Não nasceu para competir pela maior quantidade de funcionalidades.

Não nasceu para impressionar investidores.

O Ink System nasceu dentro de um estúdio de tatuagem, sendo utilizado diariamente em situações reais.

Cada ferramenta existente foi criada porque um problema real precisou ser resolvido.

Por esse motivo, o crescimento do sistema será sempre guiado pela experiência prática e nunca pela adição indiscriminada de funcionalidades.

Esta Constituição estabelece os princípios permanentes que deverão orientar toda decisão de arquitetura, produto e desenvolvimento.

Nenhuma implementação poderá contrariar este documento sem uma decisão formal de alteração desta Constituição.

## ARTIGO 1 — A MISSÃO

A missão do Ink System é organizar o funcionamento de um estúdio de tatuagem de forma simples, intuitiva e confiável.

Todo recurso existente deve reduzir trabalho.

Nenhum recurso poderá existir apenas para aumentar a lista de funcionalidades.

O sistema deve sempre priorizar clareza sobre complexidade.

## ARTIGO 2 — A FONTE DA VERDADE

Existe apenas uma fonte oficial de desenvolvimento.

Essa fonte é o Laboratório P&D.

Projeto: `inq-saas`

O Laboratório P&D é a Mãe.

Toda implementação nasce nele.

Toda correção nasce nele.

Toda melhoria nasce nele.

Toda auditoria acontece primeiro nele.

Nenhuma funcionalidade nasce diretamente em qualquer versão comercial.

## ARTIGO 3 — O INK SYSTEM 1.0

*(Artigo emendado em 2026-08-06 — o texto original tratava o Ink System 1.0 como "Laboratório de Produto"; corrigido para eliminar a contradição com a decisão arquitetural definitiva.)*

O Ink System 1.0 é o produto.

Não é um ambiente de desenvolvimento.

Não é um Laboratório de Produto.

Ele representa a versão comercial do Ink System, ainda não lançada publicamente.

O primeiro usuário do Ink System 1.0 será o próprio criador do sistema. Ele utilizará o produto diariamente e fará a descoberta de melhorias a partir desse uso real.

Toda melhoria identificada no Ink System 1.0 deverá retornar à Mãe. Somente após implementada, validada e aprovada na Mãe, ela poderá compor um novo Release do Ink System 1.0.

Jamais serão feitas implementações diretamente no Ink System 1.0.

## ARTIGO 4 — O SITE COMERCIAL

O projeto `ink-system-plataform` possui apenas uma missão:

Comercializar o Ink System.

Ele não é o CRM.

Ele não é o Laboratório.

Ele não é ambiente de desenvolvimento.

Sua responsabilidade é:

- apresentar o produto;
- captar novos estúdios;
- realizar vendas;
- executar cobrança;
- realizar onboarding;
- administrar assinaturas;
- administrar licenças.

Todo o restante pertence ao produto.

## ARTIGO 5 — O CICLO OFICIAL DE EVOLUÇÃO

Toda melhoria seguirá obrigatoriamente este ciclo:

Ideia → Discussão → Arquitetura → Auditoria → Implementação na Mãe → Validação → Uso no Ink System 1.0 → Nova melhoria identificada → Retorno para a Mãe → Nova implementação → Novo Release

Nenhuma etapa poderá ser ignorada.

## ARTIGO 6 — O RELEASE

Um Release nunca nasce diretamente.

Um Release é uma fotografia aprovada da Mãe.

O Release representa apenas um estado estável do desenvolvimento.

A Mãe continua evoluindo.

O Release permanece estável.

Quando novas melhorias forem aprovadas, um novo Release será criado a partir da Mãe.

Jamais o contrário.

## ARTIGO 7 — O CÓDIGO

Existe apenas um lugar onde o código evolui.

A Mãe.

Todo o restante recebe uma fotografia desse código.

Nunca serão mantidas duas evoluções paralelas.

Nunca existirão correções duplicadas.

Nunca existirão funcionalidades implementadas apenas no Release.

## ARTIGO 8 — O BANCO DE DADOS

O patrimônio do cliente é o banco de dados.

O código pode mudar.

A interface pode mudar.

O Release pode mudar.

O banco permanece.

Toda alteração estrutural deverá preservar integralmente os dados dos estúdios.

Nenhum Release poderá exigir reinicialização do banco.

Toda evolução deverá acontecer por migração compatível.

## ARTIGO 9 — O PRODUTO

O Ink System deverá permanecer simples.

Sempre que existir dúvida entre:

- adicionar uma funcionalidade;
- simplificar uma existente;

a simplificação será considerada a primeira alternativa.

Complexidade somente será aceita quando resolver um problema real.

## ARTIGO 10 — IMPLEMENTAÇÃO

Quem define o produto é a arquitetura.

Quem valida é a auditoria.

Quem implementa é a engenharia.

Nenhuma implementação deverá alterar a arquitetura sem aprovação.

## ARTIGO 11 — DECISÕES

Toda decisão permanente deverá ser documentada.

Nenhuma decisão importante deverá depender exclusivamente da memória das conversas.

A documentação oficial sempre prevalecerá.

## ARTIGO 12 — O PRINCÍPIO FUNDAMENTAL

Existe apenas uma regra absoluta dentro do Ink System.

Toda melhoria nasce na Mãe.

Todo o restante do ecossistema existe apenas para validar, comercializar ou distribuir aquilo que nasceu nela.

Enquanto esse princípio for respeitado, o sistema poderá crescer indefinidamente sem perder sua coerência arquitetural.

## CLÁUSULA FINAL

Esta Constituição representa a identidade permanente do Ink System.

Arquitetura, Produto, Desenvolvimento, Auditoria, Roadmap, Releases e qualquer decisão futura deverão respeitar os princípios aqui definidos.

Qualquer alteração nesta Constituição deverá ocorrer por decisão formal, documentada e aprovada antes de produzir efeitos no restante do projeto.
